# 本地服务管理平台 (Local Service Manager) — 项目文档汇总

> 版本：v1.0 | 日期：2025-07 | 状态：Sprint 3 已交付

---

## 1. 产品概述

本地服务管理平台是一个基于 **Tauri v2** 的跨平台桌面应用，用于管理本地开发环境中的多个微服务。提供可视化的服务启停控制、系统资源监控（CPU/内存/GPU）、实时日志查看和 YAML 配置编辑等功能。

| 维度 | 说明 |
|------|------|
| 产品定位 | 本地开发服务一站式管理工具 |
| 目标平台 | macOS (Apple Silicon + Intel)、Windows 10/11 |
| 管理服务 | antibody_annotation、argo_portal、model_graph_web、ollama |
| 核心能力 | 服务启停、资源监控、日志查看、配置编辑、系统托盘 |
| 技术栈 | Tauri v2 + Rust + React 18 + TypeScript + Ant Design 5 |

### 解决的痛点

| 痛点 | 现状 | 解决方案 |
|------|------|----------|
| 服务分散难管理 | 多个终端窗口逐个启动，状态不可见 | 统一面板，一键启停，实时状态 |
| 资源占用不明 | 不知道哪个服务消耗了多少资源 | CPU/内存/GPU 实时监控仪表盘 |
| 日志分散难排查 | 日志散落各终端，缺乏搜索过滤 | 虚拟滚动日志查看器，支持搜索和流过滤 |
| 手动操作繁琐 | 逐个启停，无批量能力 | 批量操作、系统托盘快捷菜单 |

## 2. 需求规划

### 目标用户

- **本地开发者**：日常需要同时运行 3-5 个微服务的后端/全栈开发者
- **AI/ML 工程师**：需要监控 GPU 使用率（ollama 等推理服务）的算法工程师

### 用户场景

| 场景 | 描述 | 频次 |
|------|------|------|
| 每日开发启动 | 一键启动全部或部分服务，快速进入开发状态 | 每天 1-2 次 |
| 调试排错 | 查看特定服务的实时日志，搜索错误关键字 | 按需 |
| 资源排查 | 发现机器卡顿，定位是哪个服务占用过高 | 按需 |
| 配置调整 | 修改服务启动参数、环境变量、端口等 | 低频 |

### 优先级矩阵

| 优先级 | 模块 | 理由 |
|--------|------|------|
| **P0** | 服务管理（CRUD + 启停）、资源监控 | 核心价值，无此不可用 |
| **P1** | 系统托盘、日志查看器 | 提升日常使用效率 |
| **P2** | YAML 配置编辑器、GPU 监控 | 增强体验，非阻塞 |
| **P3** | 自动启动、通知提醒、主题切换 | 锦上添花 |

## 3. PRD 摘要（68 条 EARS 原则需求）

### Ubiquitous — 系统始终满足的约束

| ID | 需求描述 |
|----|----------|
| U-01 | The system shall store all configuration data in `~/.local-service-manager/config.yaml` |
| U-02 | The system shall persist service definitions across application restarts |
| U-03 | The system shall support both macOS and Windows platforms |
| U-04 | The system shall use Tauri v2 IPC for all frontend-backend communication |
| U-05 | The system shall run as a single-instance application (prevent duplicate launch) |
| U-06 | The system shall display a system tray icon when running |
| U-07 | The system shall refresh resource metrics every 2 seconds by default |
| U-08 | The system shall use the local shell (bash/zsh on macOS, Git Bash on Windows) to execute service commands |
| U-09 | The system shall maintain a maximum of 10,000 lines in the in-memory log buffer per service |
| U-10 | The system shall provide mock API responses when running in browser-only mode (no Tauri runtime) |

### Event-driven — 由事件触发的行为

| ID | 需求描述 |
|----|----------|
| E-01 | When the user clicks "Start" on a service, the system shall spawn the configured shell command as a child process |
| E-02 | When the user clicks "Stop", the system shall send SIGTERM and clean up the entire process tree |
| E-03 | When the user clicks "Restart", the system shall stop the service, wait for exit, then start again |
| E-04 | When the user clicks "Batch Start", the system shall start all selected services sequentially with a 2-second interval |
| E-05 | When the user clicks "Batch Stop", the system shall stop all selected services in parallel |
| E-06 | When a service process exits unexpectedly, the system shall update its status to "error" and record the exit code |
| E-07 | When the user selects a service in the log viewer, the system shall fetch and display the latest 500 log lines |
| E-08 | When the user types in the log search box, the system shall filter log lines in real-time (client-side) |
| E-09 | When the user selects "stdout" or "stderr" from the stream filter, the system shall show only matching log entries |
| E-10 | When the "auto-scroll" toggle is on, the system shall automatically scroll to the latest log entry on each refresh |
| E-11 | When the user saves the YAML config, the system shall validate YAML syntax before writing to disk |
| E-12 | When the tray icon is clicked (left-click), the system shall show/hide the main window |
| E-13 | When the tray icon is right-clicked, the system shall display a context menu with service status and quick actions |
| E-14 | When the user clicks "Add Service", the system shall open a modal form with name, command, working directory, and URL fields |
| E-15 | When the user clicks "Delete Service", the system shall show a confirmation dialog before removing |

### Unwanted — 异常/故障处理

| ID | 需求描述 |
|----|----------|
| UW-01 | If the config file is missing or corrupted, then the system shall create a new default config |
| UW-02 | If a service command fails to spawn (e.g., binary not found), then the system shall display an error message and set status to "failed" |
| UW-03 | If the config file write fails (permission denied), then the system shall show an error notification and retain the in-memory state |
| UW-04 | If the YAML editor content is invalid syntax, then the system shall highlight the error and prevent saving |
| UW-05 | If a GPU query command fails (no GPU driver), then the system shall display "N/A" instead of crashing |
| UW-06 | If the log file exceeds 10MB, then the system shall truncate from the beginning while preserving the last 10,000 lines |
| UW-07 | If the resource monitor fails to read system stats, then the system shall display the last known values with a "stale" indicator |
| UW-08 | If the application is closed while services are running, then the system shall prompt the user to confirm (configurable) |
| UW-09 | If a service takes longer than 30 seconds to start, then the system shall show a "starting..." timeout warning |
| UW-10 | If the Tauri IPC bridge is unavailable, then the frontend shall fall back to mock mode automatically |

### State-driven — 在特定状态下的行为

| ID | 需求描述 |
|----|----------|
| S-01 | While a service is "running", the system shall display a green indicator and enable the Stop/Restart buttons |
| S-02 | While a service is "stopped", the system shall display a gray indicator and enable the Start button only |
| S-03 | While a service is "starting" or "stopping", the system shall display a spinning indicator and disable all action buttons |
| S-04 | While a service is in "error" state, the system shall display a red indicator with the last error message as a tooltip |
| S-05 | While the system tray is active, the system shall update the tray menu dynamically to reflect current service statuses |
| S-06 | While CPU usage exceeds 80%, the system shall highlight the CPU metric in orange |
| S-07 | While memory usage exceeds 90%, the system shall highlight the memory metric in red |

### Optional — 可选功能

| ID | 需求描述 |
|----|----------|
| O-01 | Where an NVIDIA GPU is detected, the system shall display GPU utilization and memory usage |
| O-02 | Where a service has a URL configured, the system shall provide a "Open in Browser" quick action button |
| O-03 | Where the user enables auto-start, the system shall register the application to launch on system login |
| O-04 | Where the user enables notifications, the system shall send a desktop notification when a service crashes |

### 前端路由

| 路由 | 页面 | 说明 |

### 数据模型

```typescript
// 服务配置
interface ServiceConfig {
  id: string;           // 唯一标识
  name: string;         // 显示名称
  command: string;      // 启动命令
  workDir?: string;     // 工作目录
  env?: Record<string, string>;  // 环境变量
  url?: string;         // 服务访问 URL
  autoStart?: boolean;  // 是否自动启动
}

// 运行时状态
interface ServiceRuntime {
  config: ServiceConfig;
  status: "running" | "stopped" | "starting" | "stopping" | "error" | "failed";
  pid?: number;
  startTime?: string;
  exitCode?: number;
}

// 日志条目
interface LogEntry {
  timestamp: string;
  stream: "stdout" | "stderr";
  line: string;
}

// 资源快照
interface ResourceSnapshot {
  cpuPercent: number;
  memoryUsedMB: number;
  memoryTotalMB: number;
  gpuUtilization?: number;
  gpuMemoryUsedMB?: number;
  gpuMemoryTotalMB?: number;
}
```

### 跨平台 GPU 检测策略

| 平台 | GPU 类型 | 检测命令 |
|------|----------|----------|
| Linux | NVIDIA | `nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total --format=csv,noheader` |
| macOS | Apple Silicon / AMD | `ioreg -l \| grep \"PerformanceStatistics\"` (Apple Silicon Metal) |
| Windows | NVIDIA / AMD | `wmic path Win32_VideoController get name,AdapterRAM` |

## 7. 上线风险清单

| 风险 | 等级 | 说明 | 缓解措施 |
|------|------|------|----------|
| Windows Git Bash 依赖 | 🟡 中 | Windows 下进程管理依赖 Git Bash 的 shell 环境 | 文档明确标注前置条件；后续可探索 PowerShell 原生支持 |
| Tauri v2 API 稳定性 | 🟡 中 | Tauri v2 仍在活跃开发，API 可能变更 | 锁定依赖版本；关注官方 changelog |
| GPU 检测兼容性 | 🟡 中 | 不同 GPU 厂商/驱动版本输出格式可能不同 | 已实现三家主流方案；增加 fallback 逻辑 |
| 大日志内存管理 | 🟢 低 | 日志行数过多可能导致前端卡顿 | 环形缓冲限制 10000 行；虚拟滚动仅渲染可视区域 |
| 进程清理不彻底 | 🟡 中 | kill 父进程后子进程可能残留（孤儿进程） | 已实现进程树遍历清理 |
| macOS 沙盒限制 | 🟢 低 | Tauri 打包的 macOS 应用默认有沙盒限制 | 配置 entitlements 声明所需权限 |
